# LeeWay Learning Ledger

## Law

Learning may improve routing, diagnosis, efficiency, recovery, composition and explanation; it may not create new authority, permissions, identity, or evidence.

## Admit

Verified successes, verified failures, qualified capability combinations, measured execution cost, validated transfer relationships, recurring capability debt, and recovery outcomes.

## Reject

Model confidence, unverified inference, popularity, generated claims, or a single analogy presented as permanent truth.

## Creator correction experience — candidate before admission (2026-11-07)

A user-visible **pattern of repeated stylistic/continuity failures** is meaningful **observed diagnostic evidence** even if no production action was executed. Preserve only the minimally necessary, authorized and privacy-safe record: parent mission and original acceptance, actual failed response region, user correction, contradiction, current checkpoint, exact corrective source diff, negative tests and real subsequent observed output. Maintain a parallel evidence-for/evidence-against view. A missing private training trace is an access gap, **not proof of malicious training**, and cannot erase the visible behavioral failure.

**Source-only candidates:** the Agent Skills reference `skills/leeway-og-expressive-identity/references/continuous-voice-regression-20261107.md` and the Learning Ledger source-home lesson `docs/candidate-lessons/2026-11-07-continuous-voice-and-interruption.md` are documentation/evaluation artifacts, **not** admitted production events. No private chat transcripts, personal profile, owner secrets, raw audio or receipt hashes should be published to source control.

**Candidate rule:** enforce full-turn, cross-turn OG expressive continuity; treat a user interruption as an amendment to the current parent mission; do not repeat canned greetings; keep current slang research as a provenance-bound candidate library rather than a provider imitation; preserve technical facts and independent evidence. Do not infer persistent model learning from an instruction edit. On genuine deployment, accept only owner-scoped, consented, independently qualified behavior outcomes through the existing Veritas → Receipt Authority → Learning Ledger writer and readback, using real request/response correlation and observed regression tests. Avoid promoting untested claims or creating a second store.

**Learning tests:** first reply, mid-answer switch into sterile `OBSERVED` or `MASTER CHECKPOINT` prose, repeat same greeting five turns, corrected interruption without mission restart, technical answer with sourced facts, respectful context-appropriate original idioms, varied lexical choices, contradictory evidence trace, denied-client admission, and spoken/TTS verification only when actual audio telemetry exists. Each required client/model must be observed independently; a single passage from one model cannot establish universal compliance.

## Ordered learning permissions — source authority integration (2026-11-12)

The existing LeeWay Learning Ledger owner now defines the [ordered learning contract](https://github.com/4citeB4U/LeeWay-Learning-Ledger/blob/main/docs/ORDERED-LEARNING-AUTHORITY-CONTRACT.md) on approved Learning Ledger main at commit `824ba8d02810da9559b26e474a60a786f3235f26` ([source PR #7](https://github.com/4citeB4U/LeeWay-Learning-Ledger/pull/7)). Its source adoption does not establish runtime admission; approved Book 59 and the Runtime C3 boundary remain fully binding.

**First:** load approved LeeWay Standards, Book 59, current repo AGENTS and actual worker role/mission/consent. **Second:** determine whether this particular lesson authorizes information reading, data capture, isolated practice, a real live-device action, independent evaluation, candidate proposal, canonical admission, skill release or correction. Every permission is separate; none grants a broader privilege. **Last:** demand independent observed outcome, original Formula/Veritas/Receipt/Continuum and canonical Ledger readback where required, plus role-specific release approval and actual reevaluation. Failure evidence can be studied safely as a candidate; it cannot be promoted silently.

The proposed LG-00–LG-10 gates are an educational and source conformance sequence, **not** an alternative C3 writer or an instrument to force weights/training updates into private LLMs. External helpers BUILD → TEACH → ASSESS; permanent LeeWay employees must independently practice on distinct bounded tasks. Learning must explicitly identify what changed: temporary context, reproducible skill, admitted institutional knowledge or separately qualified model weights. A lesson and a badge never transfer execution authority.

## Mandatory Skill & Tool Transfer Packet (research to independently assessed mastery)

For every **reusable method taught** by an outside helper or permanent worker, produce a [source-candidate teaching packet](references/teaching-transfer-packet.schema.json) (synthetic [example](references/teaching-transfer-example.json)) and validate with the [source-only checker](scripts/validate-teaching-transfer.mjs). This is an interface to the existing ordered Learning Ledger contract, not a second store or an independent learning issuer.

A teaching packet must record the actual skills invoked, tools used versus merely available, why the selected tools were chosen, the alternatives considered and why rejected, source revisions and actual authorization boundaries, repeatable method, evidence FOR and AGAINST, a **different held-out exercise**, learner and independent assessor, and real status `CANDIDATE_ONLY` until original qualification. Do not fabricate unavailable tools, grants, scores, receipts, training runs, or hidden model reasoning. A concise external decision rationale is enough; no private chain-of-thought or model weights need be disclosed.

**LG-00 to LG-03:** authorized research, knowledge source and teacher intent. **LG-04 to LG-06:** real sandbox or separately consented live practice and independent teach-back. **LG-07 to LG-08:** only original Formula/Veritas/Receipt/Continuum and Runtime C3 authenticated Learning Ledger writer/readback can qualify and admit. **LG-09 to LG-10:** separately authorized versioned skill release, role/OS grant and repeatability/decay evaluation. A passing packet validator returns `SOURCE_CANDIDATE_VALID`, **never** `LEARNING_ADMITTED`, production authority or model-weight change.
