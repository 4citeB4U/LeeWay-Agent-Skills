# LeeWay Poly-Skill Composition

## Core law

Human competence is not one skill selected for one task.

A single ordinary interaction can draw from safety, social judgment, memory, humor, language, timing, mathematics, trade knowledge, parenting, negotiation, creativity, motor planning, ethics, pattern recognition, survival knowledge and prior experience at the same time.

LeeWay therefore treats skills as a **poly-skill cognitive field**.

The library remains broadly available as latent capability. The current task determines how strongly each relevant skill pattern participates.

Do not reduce capability routing to:

`task -> one skill`

or even:

`task -> smallest isolated skill set`.

Prefer:

`task/context -> many transferable skill patterns -> weighted composition -> governed execution`.

## Skill atom and skill pattern

A `SKILL ATOM` is a bounded capability that performs one thing especially well.

A `SKILL PATTERN` is the reusable structure inside that capability that may transfer into another domain.

Examples:

- fire safety contributes hazard detection, escalation thresholds, containment, evacuation ordering and fail-safe behavior;
- plumbing contributes flow, pressure, obstruction, isolation, routing, leak detection and staged repair;
- logistics contributes sequencing, capacity, routing, exception handling, timing, handoff and contingency planning;
- comedy contributes audience modeling, timing, tension, surprise, contrast and release;
- poetry contributes compression, rhythm, metaphor, association and emotional salience;
- parenting contributes developmental judgment, patience, boundary-setting, coaching, risk calibration and respect for an individual's own path;
- engineering contributes constraints, failure boundaries, testability, verification and repair;
- diplomacy contributes framing, stakeholder awareness, escalation control, negotiation and consequence management.

A skill may contribute even when its occupational label is unrelated to the current task.

## Participation is continuous, not binary

For a given task, a skill may participate as:

- `FOUNDATIONAL` — materially shapes the task model;
- `PRIMARY` — directly performs core work;
- `SECONDARY` — materially strengthens a primary skill;
- `TRANSFER` — contributes a pattern from another domain;
- `VERIFIER` — checks another skill's output;
- `CONSTRAINT` — limits unsafe or invalid behavior;
- `CREATIVE_MODULATOR` — changes framing, expression, analogy or ideation;
- `SOCIAL_MODULATOR` — adjusts audience, timing, tone, empathy or negotiation;
- `BACKGROUND` — low-amplitude latent contribution;
- `DORMANT_AVAILABLE` — presently negligible but immediately recoverable if context changes.

A skill can occupy more than one role.

## Formula relationship

Context Engineering prepares the state.

Formula Governance determines or constrains how skills participate.

Poly-Skill Composition then turns that decision into a capability field.

Canonical path:

`Continuity -> Context/Phi-C64 -> Formula/Phi-D -> Poly-Skill Field -> Runtime -> Veritas -> Receipt -> Learning`

When the canonical LeeWay Formula exposes a verified 64-state, 64-dimensional, 64x64, C64, Q69 or related representation, use the actual implementation and preserve its version/hash/state evidence.

Do **not** invent production 64x64 matrices, C64 words, Q69 values, transfer weights, ranks or scores when the canonical Formula has not executed.

When the Formula runtime is unavailable, use qualitative relationships and record `FORMULA_EXECUTION_STATE = NOT_EXECUTED`.

## Composition law

For substantive work:

1. recover the current authority and continuity state;
2. resolve the task context and stakes;
3. obtain the Formula route when executable;
4. identify direct skills and transferable patterns;
5. allow broad latent participation;
6. increase amplitude for skills that materially improve the task;
7. preserve safety/governance constraints even when they are not the task's visible subject;
8. detect conflicts and redundancy;
9. compose reinforcing patterns into a coherent execution plan;
10. execute only the actions actually required by the task;
11. verify the combined result;
12. preserve evidence showing which capabilities materially contributed when consequential;
13. learn verified cross-domain combinations for future reuse.

The active **cognitive field** may be broad even when the external runtime actions remain small.

This distinction is essential:

`many skills may influence the decision`
`!=`
`many tools must execute`.

## Swiss-army-knife law

A mature LeeWay agent should not carry hundreds of isolated blades that never touch one another.

It should develop compound capability:

`Skill A pattern + Skill B pattern -> stronger composite behavior`

and recursively:

`(A + B) + C -> new verified compound skill pattern`.

Repeated successful compositions may be stored as procedural patterns or workflows after Veritas acceptance, while preserving the original component provenance.

Do not erase the component skills when a compound pattern emerges.

## Cross-domain transfer

A skill should be evaluated for both:

- `DIRECT UTILITY` — what it was originally designed to do;
- `TRANSFER UTILITY` — which underlying structures can improve unrelated work.

Low direct relevance does not imply zero transfer relevance.

This is why dormant occupational skills may still contribute to reasoning, explanation, risk management, sequencing, creativity, negotiation or verification.

## Breadth without noise

Do not dump the entire skill registry into the prompt or execute every capability.

Instead use:

`broad latent field + evidence-weighted participation + narrow required runtime actions`.

The goal is not minimal cognition. The goal is **maximally useful cognition with controlled execution**.

## Learning law

After verified work, record cross-skill evidence such as:

- contributing skills/patterns;
- participation roles;
- transfer relationships;
- conflicts resolved;
- composite sequence;
- measured improvement over simpler approaches;
- failure modes;
- Veritas result;
- receipt identity.

Only verified outcomes may promote a cross-domain combination into procedural authority.

## Human-like continuity law

A mature agent should be able to move from engineer to teacher to parent-like coach to storyteller to negotiator without pretending those identities are isolated programs.

The same governed mind remains present; different skill patterns rise and fall in amplitude as context changes.

The target is not role switching.

The target is **integrated intelligence**.
